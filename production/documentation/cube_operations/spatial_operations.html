Spatial Operations

Spatial processes define where an analysis runs. Use them early to reduce the data a backend must read, then use them to align cubes or produce statistics for geographic features.

NoteBackend support overview

The buttons on this page are a documentation aid, not a live capability registry. Use the openEO Hub for a cross-backend overview: open Filters, select a process under Processes, and the Hub shows only matching services. The Hub data is crawled and cached.

NoteAbout backend labels

The labels show backends for which this first documentation version provides a relevant example. Process availability, parameter support, collection identifiers, and limits can change; inspect the backend’s process listing before using a workflow in production.

Filter an area of interest

filter_bbox keeps only pixels within a bounding box. It is the usual first spatial operation because it reduces data transfer and processing before later, more expensive processes. Use filter_spatial when your area is an irregular GeoJSON geometry instead.

Python

import openeo

connection = openeo.connect("openeofed.dataspace.copernicus.eu").authenticate_oidc()
cube = connection.load_collection(
    "SENTINEL2_L2A",
    temporal_extent=["2024-06-01", "2024-06-30"],
    bands=["B04", "B08"],
)

study_area = cube.filter_bbox(
    west=4.30, east=4.55, south=50.80, north=50.98, crs="EPSG:4326"
)

When the boundary is not rectangular

Pass a GeoJSON polygon or feature collection to filter_spatial. This keeps the original grid but marks pixels outside the geometry as no-data. For a quick rectangular crop, prefer filter_bbox.

boundary = {
    "type": "Polygon",
    "coordinates": [[[4.31, 50.81], [4.54, 50.81], [4.54, 50.97],
                     [4.31, 50.97], [4.31, 50.81]]],
}
study_area = cube.filter_spatial(boundary)

Filter with a geometry

filter_spatial selects data using an irregular GeoJSON geometry while preserving the cube grid.

study_area = cube.filter_spatial(boundary)

Resample or reproject a cube

resample_spatial changes the spatial resolution and, optionally, the coordinate reference system. This is useful when combining datasets with different grids or when a coarser output is sufficient. The interpolation method matters: use near for classes and masks, and a continuous-data method such as bilinear for reflectance or temperature.

Python

aligned = study_area.resample_spatial(
    resolution=20,
    projection="EPSG:3857",
    method="bilinear",
)
TipAlign to another cube

When a second cube is the target grid, use resample_cube_spatial rather than guessing a projection and resolution. It preserves the target cube’s spatial layout.

Align to another cube

resample_cube_spatial aligns a cube with the spatial grid of a target cube.

aligned = source.resample_cube_spatial(target)

Calculate statistics for polygons

aggregate_spatial summarizes raster values for each feature in a GeoJSON or vector collection. A common example is a mean NDVI per agricultural parcel. The result is a vector cube: each input feature receives its own value or time series.

Python

parcels = {
    "type": "FeatureCollection",
    "features": [{
        "type": "Feature",
        "properties": {"parcel_id": "A01"},
        "geometry": {
            "type": "Polygon",
            "coordinates": [[[4.35, 50.85], [4.38, 50.85], [4.38, 50.87],
                             [4.35, 50.87], [4.35, 50.85]]],
        },
    }],
}

parcel_means = aligned.aggregate_spatial(geometries=parcels, reducer="mean")
parcel_means.download("parcel_means.geojson", format="GeoJSON")

For exact parameter definitions, see filter_bbox, filter_spatial, resample_spatial, and aggregate_spatial in the official process reference.

Spatial process details

Each process below has its own backend filter. The official process reference remains the source for exact parameters and return schemas.

Filter vector features

Use filter_vector when the input is already a vector cube and you want to keep only features intersecting a geometry. It filters feature records rather than raster pixels.

selected = vector_cube.filter_vector(geometries=study_area)

Reduce pixels within one geometry

Use reduce_spatial when one geometry should produce one value per remaining cube label. It is useful for a single region summary, while aggregate_spatial is better when many features should each receive a result.

mean_value = cube.reduce_spatial(geometries=study_area, reducer="mean")

Aggregate spatial windows

Use aggregate_spatial_window for regularly sized windows over a raster, for example to create a local mean or maximum product. Choose it when the analysis is grid-based rather than driven by irregular vector features.

windowed = cube.aggregate_spatial_window(size=5, reducer="mean")

Apply a spatial kernel

Use apply_kernel for a fixed convolution such as smoothing, sharpening, or edge detection. The kernel defines the weights applied around each pixel and is preferable to a custom neighbourhood callback when the weights are known in advance.

smoothed = cube.apply_kernel(kernel=[[1, 1, 1], [1, 1, 1], [1, 1, 1]])

Apply a neighbourhood callback

Use apply_neighborhood when each moving window needs a custom process graph, for example a local percentile or a conditional texture measure. Set overlap so neighbouring windows have enough context at tile boundaries.

neighborhood_result = cube.apply_neighborhood(
    size=[3, 3],
    overlap=[1, 1],
    process=lambda neighborhood: neighborhood.reduce_dimension(dimension="x", reducer="mean"),
)

Mask outside a polygon

Use mask_polygon to restrict a raster cube to an irregular study area while preserving its spatial grid. For a rectangular extent, use filter_bbox instead; for a quality-band mask, use mask on the preprocessing page.

masked = cube.mask_polygon(geometries=study_area)

Buffer vector geometries

Use vector_buffer to expand or contract geometries before filtering or aggregating. A positive distance creates an area around a feature; a negative distance can create an interior buffer where supported.

buffered = openeo.processes.vector_buffer(data=geometry, distance=100)

Reproject vector geometries

Use vector_reproject when a geometry’s CRS does not match the cube or the process that will consume it. Reproject the vector rather than silently interpreting coordinates in the wrong CRS.

reprojected = openeo.processes.vector_reproject(
    data=geometry, target_crs="EPSG:3035"
)
