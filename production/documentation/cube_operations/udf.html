User Defined Functions

Run custom Python or R logic on the backend

A User Defined Function (UDF) is custom Python or R code executed within an openEO process graph. Use it when standard processes do not express the required calculation.

NoteBackend support overview

The buttons on this page are a documentation aid, not a live capability registry. Use the openEO Hub for a cross-backend overview: open Filters, select a process under Processes, and the Hub shows only matching services. The Hub data is crawled and cached.

Apply a UDF

run_udf passes raster or vector data to backend-managed code. The supported runtime, packages, resource limits, and data model are backend-specific, so begin with a small batch job.

Python

udf_code = """
def apply_datacube(cube, context):
    return cube * 2
"""

result = cube.run_udf(
    udf=udf_code,
    runtime="Python",
)
WarningPortability consideration

Keep UDFs small and use only packages documented by the selected backend. Standard openEO processes are generally more portable and can be optimized more easily by a backend.

See run_udf and the backend documentation for the current runtime contract.

Choose the right extension mechanism

A callback is not a UDF. With apply, apply_dimension, reduce_dimension, aggregate_temporal, aggregate_spatial, or apply_neighborhood, a Python lambda describes an openEO process graph using standardized processes; no arbitrary Python code is sent to the backend. A UDF sends backend-executed Python or R code through run_udf.

Need Preferred mechanism
Scale values, calculate an index, or reduce a dimension A standard process or callback.
Reuse a named process graph A UDP.
Apply a backend-supported ML model The backend’s ML process.
Run an algorithm unavailable as an openEO process run_udf.
Use a custom external execution environment run_udf_externally, when advertised by the backend.

UDF-related processes

Each process below has its own backend filter. The callback processes are included for comparison, but they do not execute arbitrary Python or R code on the backend.

Run a backend UDF

Use run_udf when the required algorithm cannot be expressed with standardized openEO processes. The backend executes the supplied Python or R code close to the data, subject to its runtime, package, memory, and execution limits.

result = cube.run_udf(udf=udf_code, runtime="Python")

Run an external UDF

Use run_udf_externally when the computation must run in an environment managed outside the backend. This is useful for custom dependencies, but it is less portable and may require backend-specific credentials or configuration.

result = openeo.processes.run_udf_externally(data=cube, udf=udf_code)

Apply a standardized pixel callback

Apply a standardized process callback independently to each pixel; this is not arbitrary Python execution.

scaled = cube.apply(lambda value: value * 0.0001)

Apply a standardized dimension callback

Apply a standardized callback along one cube dimension.

smoothed = cube.apply_dimension(dimension="t", process=lambda series: series.median())

Apply a standardized neighbourhood callback

Apply a standardized callback over a moving spatial neighbourhood.

result = cube.apply_neighborhood(size=[3, 3], process=lambda window: window.mean())

The Python-client guide to callbacks explains the distinction and the callback restrictions in detail.
